# Talkty for macOS — developer guide

Native macOS rebuild of Talkty (originally a Windows WPF app). Local, private
speech-to-text: press a global hotkey, speak, get text on the clipboard and
optionally auto-pasted at the cursor. Everything runs on-device via whisper.cpp.

## Stack

- **Swift 6 + SwiftUI** (views) over **AppKit** (status item, non-activating
  overlay panel, windows). Menu-bar app (`LSUIElement`), no Dock icon.
- **whisper.cpp** as the engine, vendored at a pinned commit and built into static
  libs with the Metal shader **embedded** (no `.metallib` to ship). Built with **Core
  ML** too (`WHISPER_COREML` + fallback): if a per-model encoder `.mlmodelc` sits next
  to the `.bin`, the encode pass runs on the **Neural Engine**; otherwise it falls back
  to Metal. Apple Silicon only.
- Min deployment target **macOS 14**. Dev machine is an M5 / macOS 26.

## Layout

```
Package.swift            SwiftPM manifest; computes the whisper lib path from #filePath
Sources/
  CWhisper/              C module exposing whisper.h/ggml.h (modulemap + shim.c)
  TalktyKit/             All non-UI logic (services + models). No window code.
  Talkty/                The app: AppKit/SwiftUI shell (added Phase 3)
  smoke/                 Dev CLI: proves Swift→whisper→Metal (transcribe a wav)
Vendor/                  gitignored; regenerated by Scripts/bootstrap.sh
  whisper.cpp/           pinned clone
  whisper-install/       lib/*.a + include/*.h linked by the package
Scripts/
  bootstrap.sh           clone pinned whisper.cpp + build (run once after checkout)
  build_whisper.sh       (re)build the Metal+CoreML static libs into Vendor/whisper-install
  make_app.sh            assemble + sign dist/Talkty.app  (--install → /Applications)
  make_dmg.sh            package a drag-to-Applications DMG for release
  make_coreml.sh         generate a per-model Core ML (ANE) encoder .mlmodelc
  dev_identity.sh        create the stable self-signed signing identity (TCC persists)
```

## Build & run

```bash
Scripts/bootstrap.sh                 # one-time: vendor + build whisper (needs cmake)
swift build                          # build everything
.build/debug/smoke <model.bin> <audio.wav> [lang]   # engine smoke test
```

`brew install cmake` is required for the whisper build. Xcode is optional —
open `Package.swift` in it to edit; the runnable `.app` is assembled by a
script and ad-hoc signed (no Apple Developer account needed).

## Hard-won gotchas

- **Teardown abort.** ggml-metal's global device is freed by a C++ static
  destructor at process exit, which asserts its (keep-alive) residency set is
  empty and otherwise `abort()`s (exit 134). It does NOT fire on mid-run model
  switches — only at process teardown. Fix: at quit, after flushing state and
  `whisper_free`, terminate via `_exit(0)` to bypass those destructors. The app's
  quit handler must do its own cleanup first (save settings, flush logs).
- **First-load cost.** The embedded Metal shader compiles on first init
  (~6 s, cached by the OS afterward → ~0.1 s). Warm the engine on a background
  thread at launch so the cost is hidden.
- **Link order.** Static libs link dependents-before-dependencies; `ggml-base`
  last, and `whisper.coreml` right after `whisper`. See `Package.swift`.
- **Core ML (ANE) encoder.** Built with `WHISPER_COREML` + `WHISPER_COREML_ALLOW_FALLBACK`.
  whisper looks for `<model>-encoder.mlmodelc` next to the `.bin`; present → encode on the
  Neural Engine, absent → Metal (purely opt-in). Generate with `Scripts/make_coreml.sh
  <model>` (torch/coremltools via `uv`; no Xcode needed — coremltools compiles the
  `.mlmodelc`). First ANE load compiles for the device (slow once, OS-cached).
- **Settings decode is lenient — keep it.** `AppSettings`/`UserHints` have a hand-written
  `init(from:)` (`decodeIfPresent ?? default`). `SettingsStore` resets to defaults on any
  decode throw, and the synthesized decoder throws on a missing key — so a new non-optional
  field would wipe every user's config on update. When adding a setting, add it to the
  `CodingKeys` enum AND a decode line (there's a regression test).

## Behavior parity notes (from the Windows original)

- Audio: 16 kHz mono float. Silence-trim RMS threshold 0.01, 100 ms window,
  200 ms safety margin.
- Whisper: greedy, temperature 0, `best_of` 1, no context carryover; threads =
  logical/2 capped at 8.
- Post-processing order: JoinSegments (re-join `period + lowercase` false
  breaks) → CleanupPunctuation → ApplyReplacements (vocabulary) →
  StripHallucinations (`Thanks/Bye/Subscribe/[MUSIC]/`, 3+ ellipsis, trailing
  "you").
- Hotkey default Alt+Q (configurable); ESC cancels during recording.
- Storage: `~/Library/Application Support/Talkty/` (settings.json, history.json,
  Logs/, Models/). History capped at 50.

## Conventions

- TalktyKit is UI-agnostic (Foundation/AVFoundation/CoreGraphics/AppKit-pasteboard
  OK; no SwiftUI/window code). The app layer owns all windows and view models.
- Match the surrounding Swift style; keep services behind small protocols so they
  can be faked in tests. Critical paths only get tests (transcription
  post-processing, settings round-trip, download resume).
